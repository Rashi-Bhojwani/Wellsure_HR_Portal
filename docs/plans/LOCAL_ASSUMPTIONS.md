# Things built locally that assume a local environment

Started 2026-10-16, when the user paused Phase 1.5 (commits B to F) until after Phase 7: all AWS work, the migration and connecting
the device come last, together, as the final stage. Phases 6 and 7 are built and tested **locally**, so anything that quietly depends on
the laptop, the CI runner or a single process is recorded here **as it is written**, not found on the first deploy.

How to use it: add a row the moment you write something that works locally for a reason that will not hold on AWS. The final stage
walks this list top to bottom before the first `cdk deploy`. "Checked" is filled in then, with the date and what was seen.

_Note on row 11:_ `payroll_approvals` is the one payroll table whose rows are updated (PENDING → APPROVED → CONSUMED). The Phase 1.5 role step revokes UPDATE on every table guarded by a **truncate-blocking** trigger, and `payroll_approvals` has one (`payroll_approvals_no_truncate`), so it would have stripped the UPDATE and the app could not have decided an approval. This was found while writing this row and **fixed in P6-1**: `UPDATABLE_APPEND_ONLY_TABLES` in `backend/src/lib/dbRoles.ts` (just `payroll_approvals`) keeps UPDATE but still revokes DELETE and TRUNCATE, and the row's own trigger limits which transitions are legal. `dbRoles.test.ts` proves the app role has UPDATE on `payroll_approvals` and on no other append-only table. Any later table that needs the same treatment must be added to that list on purpose, with a test.
